# E2.3 — sqlfs

`internal/adapters/outbound/sqlfs` keeps a tree in a SQLite database, behind the
ten verbs, `Caps` and one of the three accessors. `cmd/nerved` registers it as
the kind `sqlfs` with one setting, `path`, declared public: which file a mount
writes to is what an operator has to be able to read back.

It is the first plugin whose storage outlives the process.

```
$ NERVE_CONFIG=nerve.json ./bin/nerved
mount / kind memfs {AppendOnly:false ReadDestructive:false ReadOnly:false Broadcast:false ObjectStore:false}
mount /store kind sqlfs {AppendOnly:false ReadDestructive:false ReadOnly:false Broadcast:false ObjectStore:false}
$ ls data/
tree.db  tree.db-shm  tree.db-wal
```

## What the pattern was

One row is one entry, keyed by its whole path. The other shape — a row per entry
with a parent id — makes `Rename` a single update and `ReadDir` a join; keying by
path makes `ReadDir` an index lookup on a `parent` column and `Rename` a prefix
rewrite over the subtree. Every verb but `Rename` is a path lookup, so the shape
that makes lookups free is the shape to keep, and `Rename` pays for it in two
statements inside one transaction.

The suite is the test. sqlfs runs `vfstest` and answers 51 cases, skipping the
ten that belong to the two verb sets it refuses. What it needed of its own is
only what no conformance case can see: that a tree survives being closed and
opened again, that a subtree match is not a pattern, that a cancelled context
stops a verb, and that a refused rename moves nothing.

## What surprised me

**The conformance suite passed while the code had a real bug in it.** A subtree
is matched by comparing a prefix — `substr(path, 1, length(?)) = ?` — rather than
with `LIKE ? || '%'`, because a path is an operator's string and `%` in one is an
ordinary character to everybody except `LIKE`. Written with `LIKE`, the suite
stays green: no case names a directory `100%`. `TestASubtreeMatchIsNotAPattern`
fails, and it is the only thing that does.

```
$ go test -run TestASubtreeMatchIsNotAPattern ./internal/adapters/outbound/sqlfs/
    sqlfs_test.go:73: Stat(/100x/kept) after removing a sibling = file does not exist, want the entry
```

**`substr` counts characters and `len` counts bytes.** The prefix length is
measured by SQLite, in the same units `substr` indexes in, rather than computed
in Go: passing `len(prefix)` is right for every ASCII path and wrong for the
first one with a non-ASCII name in it.

**Concatenation is a text operator.** `Truncate` pads with zero bytes, and
`data || zeroblob(n)` in SQL hands back a string: SQLite's `||` converts its
operands to text. The resize happens in Go, which makes `Truncate` a
read-modify-write and not the in-place cut the name suggests. sqlfs answers the
accessor anyway, because what the port asks is whether an entry can be cut to a
length rather than only replaced whole, and it can.

**goleak found the architectural gap, not a bug.** sqlfs holds a
`database/sql` pool, which parks a goroutine. `vfs.FileSystem` has no lifecycle
verb, and `Registry.Build` wraps every plugin in three decorators, so nothing
that comes back out of a mount table can be closed — not even by type assertion,
which the settled decision forbids anyway. A test that mounts sqlfs through the
registry leaks that goroutine and the check reports it. Closing is on the
concrete type, so a test that builds one can close it and a config-mounted one
relies on the process exiting: the `-wal` file above is that gap, visible.
Filed as nrv-mii rather than fixed here — release belongs either in the port or
in the composition root that already knows every concrete type, and that is a
decision about the port rather than about this plugin.

**One connection is a design choice with an alternative that also works.**
SQLite serialises writers whatever the pool does, so more connections buy no
write concurrency — they move the queue from Go's pool into SQLite's lock, where
running out of the wait is `SQLITE_BUSY`. Both the single connection and
`busy_timeout` absorb the contention test on their own; with neither, it fails:

```
$ go test -race -run TestConcurrentVerbsOnOneTree ./internal/adapters/outbound/sqlfs/
    contention_test.go:34: Write("/jobs/worker-4") = write begin: database is locked (5) (SQLITE_BUSY)
```

One connection is the same queue with nothing to tune. `busy_timeout` stays for
the case one connection cannot cover: a second process on the same file.

**The driver had to be pure Go.** `make build` sets `CGO_ENABLED=0` so the
binary is reproducible, which rules out a cgo SQLite before any of its merits
are considered. `modernc.org/sqlite` is a translation of SQLite into Go;
`make repro` is still green with it in.

## What I would do differently

Write the prefix-matching test before the prefix-matching code. It was written
after, from noticing that `LIKE` was the obvious spelling and the wrong one —
which is the right instinct arriving at the wrong time. The suite cannot cover
a plugin's own storage model, so a plugin's own tests are where its own traps
have to be caught, and they are the tests most easily left until the suite is
green and the work feels finished.

## What I still do not understand

Whether the lexical path helpers belong in one place. `clean`, `split` and
`chain` here do what `elements` and `samePath` do in memfs and what `localfs`
does against the host separator. Three plugins is where a rule of three would
fire, but the port says an implementation resolves a path relative to its own
mount, and each of the three resolves it into something different — a map key, a
row key, a host path. Extracting the shared half may be extracting a coincidence.

Whether `Rename`'s two statements are one operation in the sense that matters.
They are one transaction, so no reader sees half a move. But the descendant
rewrite matches rows by the prefix they had before the first statement ran, and
that is true because SQLite gathers the rows an `UPDATE` touches before it
touches any of them. Nothing in this package says so; the test that would fail
if it stopped being true is `TestRenameRewritesAWholeSubtree`, which does not
know that is what it is guarding.
