# E5.4 — Cross-user isolation, and the boundary nobody holds

`internal/core/workspace/isolation_test.go` drives one user's scope against
another's through a mount table carrying a host-backed tree, an in-memory tree
and a keyspace, and asserts the other user's world is unchanged afterwards.

The E5.1 note set the condition this had to meet: an isolation test written
against `Path` alone shows that two scopes derive paths which do not nest and
nothing about whether the store behind them keeps them apart. So every case here
runs through a real mount, and `/files` is `localfs` over a temp directory
because it is the only kind present whose containment the kernel enforces — the
only one where the derivation layer and the store layer can give different
answers.

## What the pattern was

The acceptance is negative — nothing of bob's is observable — so the shape is
one assertion reused by every case rather than one assertion per verb.
`requireBobUntouched` reads his content, his permission bits, the listing of his
workspace, and the workspaces `List` names for him. A verb that reached him
shows up as whichever of the four that verb would have caused, which is what
lets one table cover every verb against every spelling without any case knowing
what its verb does.

The verbs run against a fresh world each time. Several of them destroy alice's
own workspace, and a verb that found nothing left of hers would prove nothing
about his.

## The three layers, and the one that is missing

Each layer holds a boundary. None of them is the scope.

| Layer | Boundary it holds | Where that is tested |
|---|---|---|
| `Scope.Path` | the scope root, lexically | every climbing case here |
| `MountTable` | the mount prefix | `TestALinkCannotJoinTwoAreas` |
| `localfs` / `os.Root` | the mount root | the conformance suite's escape cases |

A symlink target under another user's subtree *in the same mount* satisfies all
three. The path is clean, both ends are in one mount, and the target is inside
the `localfs` root, so `os.Root` permits it:

```
alice.Path("/files", "peek")   ->  /files/alice/cv/peek
symlink target /files/bob/cv   ->  inside the localfs root
read /files/alice/cv/peek/secret  ->  bob's content
```

So cross-user isolation currently rests on the derivation layer alone. It holds
while every path a caller passes came from `Path`, and `Symlink` takes a second
path that nothing dispatches. `TestInsideOneMountTheScopeBoundaryIsDerivationAndNotTheStore`
pins that rather than endorsing it; closing it is structural — a scope that is a
mount, or a scoped view whose every path goes through `Path` — which E5.1 parks
for E11.3 and `nrv-rfr` carries.

## What surprised me

**Two cases passed for the wrong reason, and both were found by breaking the
code rather than by reading them.** This is the nrv-4r3 lesson
arriving a second time: a test that passes proves nothing about the test.

`TestALinkCannotJoinTwoAreas` was written over the ordinary fixture, where the
second area is `memfs`. Removing the mount table's cross-mount check entirely
left it green, because the refusal was never coming from the boundary — `memfs`
has no link verbs, so the dispatcher refused on the kind. It also reused one
link name for all three targets, so the first refusal and `EEXIST` on the rest
were indistinguishable. The case now mounts `localfs` twice and gives each
target its own name, and dies when the check goes.

`Mkdir` was the one verb that survived dropping the clamp. Every climb
in the table named a path bob already had, and `Mkdir` onto an existing entry
changes nothing observable. It was the assertion that was weak, not the verb:
`requireBobUntouched` checked that bob's entries survived and never that his
workspace held only them. Reading his workspace back and adding a climb onto a
leaf he does not have — `../../bob/cv/intruder` — catches every verb that only
ever adds.

**`Chmod` failed the harness before it failed the assertion.** A climb of `..`
lands on alice's own workspace directory, and chmod `0o600` on a directory takes
the execute bit off, so `t.TempDir` could not clean up afterwards. The mode is
`0o700` now. Worth recording because the failure was in the test framework's
teardown and read at first like a product bug.

**The store layer cannot be reached through a mount table at all.** The first
draft asserted that `localfs` refuses a link out of its root, through the table.
It does refuse — but the refusal comes from `MountTable.resolve`, which cleans
and rejects the path before the plugin is ever asked. That is exactly what the
nrv-4r3 note says about testing a plugin only through a table, and it means this
file cannot exercise the third layer even when it wants to. The comment now
names where each layer is tested instead of claiming to test all three.

## What I would do differently

Write the mutation before the assertion. Every case here was made to fail for
its own reason afterwards, and two of them needed rewriting when it turned out
they could not. Deciding what break each case is meant to catch, and breaking
that first, would have produced the same file without the two rounds.

## What I still do not understand

Whether the two-path verbs want a rule of their own. `Rename` and `Symlink` both
take a second path, and the one-path verb table cannot spell the direction that
matters — an entry carried from one scope into another — so `Rename` has a case
of its own with one end anchored in alice's real scope. It is contained because
`MountTable.pair` resolves both ends; `Symlink` is not, because only one of its
ends is a path the table dispatches. That asymmetry is the whole of `nrv-rfr`,
and I do not know whether the fix belongs to `Symlink` or to every verb that
takes a path a caller did not derive.

Whether a keyspace deserves the same scrutiny as a tree. `kvfs` has no links and
no host, so the escape surface here is `localfs`'s. But a keyspace answers for a
prefix, and what a prefix means is the store's decision rather than the port's.
Nothing in this file would notice a store that treated one user's prefix as
another's.

Pointing `Lifecycle.List` at the area root instead of user scope fails

`from.prefix != to.prefix` check in `MountTable.pair` fails
`TestALinkCannotJoinTwoAreas`.

The remaining case asserts the gap, so it fails when the gap closes rather than
when it opens. That is deliberate and `nrv-rfr` is where it is written down.
