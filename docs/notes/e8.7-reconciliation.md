# E8.7 — Commit: reconciliation against contradicting prior memories

A contradicted memory is resolved, not duplicated. Four pieces:

- `memory.Fact.Subject` and `llm.Fact.Subject` — the one question a fact answers
  ("name", "home", "work"), empty for a fact that answers none.
- `internal/core/memory/reconcile.go` — `Store.Add` writes a fact naming a subject
  as superseding every believed memory answering the same `(kind, subject)`. Only
  the last answer a batch gives to a question is written.
- `cuefact` — the name, live and work cues name a subject. No other cue does.
- `consolidate` — carries the subject to the endpoint, and declines a narrative
  that merges an answer.

## What the pattern was

E8.8 had already built the mechanism. `Supersede` plus a derived `Until` closes an
interval without editing anything, so reconciliation adds no storage. It only
decides *which* memory a fact supersedes.

The hard part was that decision. `Fact` was `{Kind, Body, Priority}`, and from those
fields "my name is Ada / my name is Bea" looks the same as "I like tea / I like
coffee": same kind, different body. E8.5's note said contradiction is a question of
meaning. There were two honest ways to answer it:

- **A model judges it.** An `llm.FactReconciler` port, like E8.6's consolidator.
- **The fact says what it answers.** An optional subject. This is the thesis applied
  to a fact: the implementation describes its own non-uniformity, here "I am
  single-valued", instead of a caller inferring it.

The second works on the laptop with no model, and it keeps the rule in the store
beside dedup. That is where a write invariant belongs.

## What surprised me

**The consolidator would have undone it.** termfold merges facts of one kind that
share words, and "I live in Dublin." with "I work in Dublin." share 0.6 of theirs.
The narrative it writes names no subject. A later "I live in Berlin." then finds no
answer to supersede, and the workspace believes Dublin and Berlin at once. I proved
this with a probe against termfold before changing anything.
`TestAnAnswerIsNotMergedAwayFromTheQuestionItAnswers` fails without the decline.
The fix is a third reason the stage declines a narrative, beside one-fact and
mixed-kind. It lives in the core stage, so every endpoint gets it.

**Batch order had to change.** Dedup keeps the first statement of a claim and
reconciliation wants the last answer, so their order matters. For `[Berlin, Dublin]`
over a believed Dublin, running the last-answer pass first leaves `[Dublin]`, and
dedup drops it: the conversation ended where it started. Running dedup first would
drop the second Dublin as a restatement and write Berlin, which is wrong. The last
answer is taken first, then dedup, then reconciliation.

**Validation moved to the top of `Add`.** E8.5 found that a bad fact is refused only
because dedup happens to keep it. The last-answer pass would silently drop an
invalid earlier answer, so `Add` now validates the whole batch before filtering
anything. That dependency is now explicit instead of accidental.

## Deliberately not done

**No model reconciler (option A).** It needs a fifth gateway capability, a laptop
adapter, and composition-root wiring in `cmd/nerved`, which nrv-df1d is changing in
parallel. Revisit it once a model extractor exists. Until then, cuefact is the only
producer of `llm.Fact`, and the subject is how it says what it means.

**No subject on preferences, "i am", decisions or instructions.** None of them has
one answer at a time. "I prefer tabs" then "I prefer vim" is two facts, and giving
the cue a subject would make the second erase the first.

**Narratives never carry a subject.** The stage declines to merge answers, so no
narrative absorbs one, and there is nothing to carry.

## What I still do not understand

Whether the subject vocabulary will stay small enough to keep in the extractor.
Three cues cover it today. A model extractor will invent subjects freely, so "home"
and "residence" become two questions and the fold will not join them. The
vocabulary may need to be declared somewhere both extractors read, but I cannot
name that place yet without the second extractor to shape it.
