# E10.6 — one consumer per job

E10.5 left the scheduler recoverable and therefore runnable twice: every process
that starts finds the same backlog, and two of them materialising one projection
write the same slice files at the same time. `schedule.Lease` is the port that
settles which one is on it, `internal/adapters/outbound/pglease` is the claim in
Postgres, and the run is bounded by the claim so exclusion granted for a while
is not held for longer.

Offline, the scheduler asserted against a lease the test drives:


## What the pattern was

**The claim is not on the tree.** The note is, and that was the obvious place to
put the claim beside it — one file per job, already there. It cannot work. The
verb set has no create-if-absent and no compare-and-swap, so two processes both
read no claim, both write one, and both believe they have it. `Write` records a
race that was already settled; it cannot settle one. So the lease is a port with
one shipped implementation behind it, and Postgres is where the row lives —
`INSERT ... ON CONFLICT DO UPDATE ... WHERE until <= now()`, where the conflict
clause runs inside the statement and of two consumers asking together exactly
one changes a row.

**Refusal is an answer, not a failure.** `Do` returns `ErrHeld` and `Recover`
passes the job over. A backlog that stopped for a held job would be waiting on a
process it cannot see, and reporting it as a failure would make a healthy pair
of nodes look broken every time they both started.

**The run is bounded by the claim.** `context.WithDeadline` at the end of the
ttl, and the clock starts before the lease is asked rather than after it answers
— a deadline computed after the round trip falls a round trip *past* the grant
the database recorded, which is the wrong side of it. Exclusion that outlives
its lease is not exclusion.

## What surprised me

**The release must not be deferred.** The first draft used `defer`, which is the
reflex, and it silently undid the whole thing: the crash model is a panic, and a
panic runs deferred functions on the way out. The dead consumer politely gave
its claim back, so the next one took the job over immediately and the test that
was meant to prove a claim outlives its holder passed for the wrong reason. A
lost host runs no defers. Calling `Release` on the return path is both simpler
and the only faithful version.

**The absolute expiry the store returns is worse than the local one.** Returning
`until` from the database and passing it to `WithDeadline` looks more correct —
the store is the authority on when the claim ends — but the deadline is then
compared against the consumer's clock, so a clock offset between the two moves
it in either direction. Computing `now + ttl` locally is immune to offset and
only exposed to drift in rate, which is negligible. The grant carries a bool.

**A holder may not retake its own live claim.** Allowing it reads as harmless
re-entrancy and is exactly the hole: a process whose two goroutines both hold
the job is two consumers, and the port cannot tell it from one.

## What I would do differently

The port took a `Grant{OK, Until}` at first, because "the lease says how long you
have" is the natural sentence. It bought nothing once the deadline was computed
locally, and it made every implementation answer a question the caller then
ignored. `(bool, error)` is the whole contract.

## What I still do not understand

**Nothing wires it.** `cmd/nerved` composes no scheduler, so the ttl, the holder
name and the claims DSN are constructor arguments with no config behind them
yet. What is unproven is the wiring, not the exclusion.

**A run longer than its ttl is cancelled, not extended.** There is no renewal,
because renewal needs a goroutine and this package deliberately holds none. That
makes the ttl a bound on how long a projection may take, which is fine while a
projection is minutes and wrong the first time one is not. Renewal driven by the
same bus that drives the job is the shape that would keep the goroutine out, and
it is not written.

**The claim is in Postgres and the tree is the system of record everywhere
else.** That is a second store in a repo whose thesis is one uniform interface,
justified only by an atomicity the interface does not have. A `Claimer` accessor
— create-if-absent, or compare-and-swap, per E1.3's rule — would put it back on
the tree and would be the honest fix, at the cost of a verb every plugin has to
answer for. I did not think one ticket's exclusion was enough evidence to add
one.
