# E9.7 — KV routes

`kv.Space` is a workspace's scratch key space: `Get`, `Put` and `Delete` under a
namespace the caller names, on the one FileSystem the mount table presents. Three
verbs, which is the whole ticket — a value is written and read whole, and there
is no history, no listing and no index over it.

## What the pattern was

`library.Registry` one field lighter. Both hold the tree and a root, take a
`workspace.Scope` per call, derive every path through `Scope.Path`, and know no
plugin. A reader who has read one has read this.

The namespace is a call argument rather than a field, which is where it differs
from the kind a registry is built with. A kind is what a process was configured
to serve; a namespace is what the caller is doing right now, and two agents in
one workspace pick their own without anything above them being reconfigured.

Every verb is asked twice, once over `memfs` and once over `kvfs`, because the
two storage shapes disagree about what a namespace is: a directory on a tree,
a prefix in a keyspace. `Put` makes the first with `Mkdir` and asks nothing of
the second, where `Mkdir` has nothing to make. Dropping that one call leaves
every tree case failing and every keyspace case green, which is the whole reason
both run:

```
$ go test ./internal/core/kv/ -count=1     # with the Mkdir removed
--- FAIL: TestPutAndGetRoundTrip (0.00s)
    --- FAIL: TestPutAndGetRoundTrip/tree (0.00s)
        space_test.go:78: Put("run"/"cursor"): put "run"/"cursor": write "/ada/hunt/run": file does not exist
```

## What surprised me

**`RemoveAll` is the wrong delete here, and only a keyspace shows it.** The
registry deletes a document with `RemoveAll`, because a document is a directory
and idempotence is what a half-finished delete needs. Copying that reasoning
gives `Delete` a blast radius: a keyspace lets a key and a prefix share a name,
so `RemoveAll` of the key `run/cursor` also takes out `run/cursor/deeper`, which
something else on the same mount put there. `Remove` tolerating `fs.ErrNotExist`
is the same idempotence without the reach — the test that catches it passes
under `RemoveAll` on a tree and fails on a keyspace.

**User scope had to be refused for a reason the registry does not have.** A
registry refuses it because listing would report workspaces as documents. There
is no listing here, so the same refusal needed its own argument, and
`workspace.Lifecycle.List` is it: that verb counts directories under a user's
root as workspaces, so a namespace written at user scope would be listed as a
workspace that nobody created and `Delete` would never remove.

**The flat-segment rule is now written four times.** `workspace.validSegment`,
`version.ValidateRefName`, `library.validName` and now this one, each with a
comment saying it is the same rule as the last. E9.1 filed it; it is `nrv-e6y`
and still open. Writing the fourth copy rather than the extraction was a scope
call, not a judgement that four is fine.

## What I would do differently

Nothing in the shape. If the ticket had asked for a fourth verb it would be
`List` over a namespace, and the argument against adding it unasked is that a
namespace is not a directory on every mount kind — `ReadDir` of a prefix answers
on both, but what it means differs enough that the verb wants its own ticket.

## What I still do not understand

**Whether a key should be allowed to hold a separator.** It is one flat segment
here, so an agent wanting `plan/step-1` uses the namespace `plan` and the key
`step-1`. A keyspace would carry the longer key happily and a tree would need
the parents made; refusing it keeps one rule over both and makes the namespace
do the nesting. Whether that is the right trade shows up when something actually
stores a tree of scratch state.

**Nothing consumes the space.** It is wired nowhere, which is where
`library.Registry` and `workspace.Lifecycle` also are: the composition root does
not name a scratch root, so no config key for one exists yet. E9.6's inbound
surface is where the root, and whether the namespace is chosen by the caller or
derived from the agent making the call, get settled.
