# E2.4 — objectfs

`internal/adapters/outbound/objectfs`: an object store behind the same ten verbs
as every other kind, claiming `ObjectStore` at every path. The store itself sits
behind one port, `Bucket`, with an S3 client over `net/http` as its shipped side.
MinIO serves that wire from `docker-compose.yml`; a hosted store serves it in
the cloud.

```
mount /scratch kind memfs    {AppendOnly:false ... ObjectStore:false}
mount /objects kind objectfs {AppendOnly:false ... ObjectStore:true}
```

## What the pattern was

The first plugin that claims a descriptor, so the first read of whether the
descriptor was worth having. E1.2's note left the question open: whether
`ObjectStore` belongs in the set at all, since the other four constrain what a
verb does and this one constrains what a path means.

It earns its place, and the conformance suite is where that shows. memfs selects
61 cases; objectfs selects 39, having dropped 25 that assume a tree and gained
the 3 that hold a plugin to prefixes. Nothing was written twice and nothing was
skipped by hand: the same `vfstest.Run` call as memfs, against a kind that
behaves differently.

The second pattern is the port inside the plugin. `Bucket` is six verbs — head,
get, put, copy, delete, list — and the prefix semantics sit entirely above it.
That is what lets the suite run offline against a bucket in a map and again
against MinIO, and be the same suite both times.

## What surprised me

**A prefix is a directory only while something is under it.** `Stat` of `/jobs`
has to answer three different ways: the object stored under that exact name, a
directory when keys sit beneath it, and `fs.ErrNotExist` when neither. Removing
the last entry under a prefix makes the directory go away with no verb having
touched it. Nothing in a tree behaves like that, and it is the whole of what
`Mkdir` returning nil is standing in for.

**A store's clock is too coarse for a promise the port makes.** The suite asserts
that `Write` moves `ModTime` forward. S3 records last-modified to the second, so
two writes in a row read as one instant and the case fails against a real store
while passing against a map. The write records the instant itself, as metadata
beside the mode. Finding this needed MinIO: no fake would have had a coarse
enough clock to fail.

**Keeping the mode costs a round trip on the wrong verb.** An object store has no
mode, so `Chmod` is a copy onto the same key with replaced metadata — and a
later `Write` would drop what it set unless the write reads the mode first. So
`Write`, the hot verb, pays a `Head` to keep `Chmod`, the rare one, meaning
something. The alternative is a mode that silently resets, which is worse than
no mode: a caller can plan around a kind that refuses, not around one that
forgets.

**`Rename` is where an object store stops pretending.** It moves one object.
There is no subtree under a name to bring along, so `/jobs` moving to `/done`
leaves `/jobs/queued` exactly where it was. The suite does not catch this — the
subtree case is one of the nineteen a tree claim gates — so it is asserted in the
plugin's own tests, which is what those are for.

**SigV4 is smaller than the SDK that carries it.** The client and the signing
are 486 lines and no new module in `go.mod`, against roughly a dozen modules for
`aws-sdk-go-v2` to reach six verbs. The part that had to be exact was not the
HMAC chain but the path: `url.URL` escapes a path by its own rules and the
signature by another, so `RawPath` is set to what the signature covers or a key
with a `+` in it signs one way and sends another.

**Refusals classify at the plugin's edge or nowhere.** `vfs.ErrTransient` only
works if something translates 503 into it. Doing that here means the retry
wrapper never learns what an HTTP status is, which is the same move as mapping a
driver error onto an `io/fs` sentinel — and it means a 400 is not retried three
times on its way to failing.

## What I would do differently

Reach for the real store earlier. The semantics were finished and green against
the map before MinIO was started, and the `ModTime` defect was sitting in it the
whole time. A fake agrees with whatever you built; the plane test is what the
fake is for, not what it proves.

## What I chose not to build

`Truncate` and the link verbs are refused through their accessors. Cutting an
object to a length means fetching it, cutting it here and storing it back —
a caller's read-modify-write with a verb's name on it — and a bucket has no
links at all.

`OpenWrite` buffers and stores at `Close`, which is what the port already
promises, so a streamed write is bounded by memory. Multipart upload is what
lifts that, and it is a second wire protocol rather than a fifth verb.

`RemoveAll` lists and deletes one key at a time. S3 has a batch delete; a
thousand keys is a thousand round trips until it is used.

## What I still do not understand

Whether `Mkdir` returning nil is the right refusal. It reports success for work
it did not do, and a caller that then calls `Stat` on what it just made gets
`fs.ErrNotExist`. `ObjectStore` is declared, so a caller can know — but a caller
that ignores the descriptor gets an answer that is technically true and reads as
a lie. The alternative, `fs.ErrInvalid`, makes every caller branch on the
descriptor before a verb that is a no-op for one kind. The conformance suite
picked the first, so it is the port's answer now.

Whether the mode belongs on `Bucket` at all. It is there because `Chmod` is in
the port above, and it makes an object this plugin wrote different from an object
another tool wrote — the second reads back as `0644` regardless. That is fine
for a store nothing else writes to and wrong for a shared bucket.
