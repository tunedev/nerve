# E2.1 — memfs

`internal/adapters/outbound/memfs`: the whole tree in memory, behind the ten
verbs, `Caps` and the accessors. `cmd/nerved` registers it under the kind name
`memfs`, so a mount table in a config file now resolves to something that
stores.

## What the pattern was

The first adapter. E1.4 made the table dispatch and E1.5 made a config document
name a plugin; this is the plugin, and it closes the loop that E1.5's note left
open — a mount that succeeds outside a test.

```
$ NERVE_CONFIG=nerve.json ./bin/nerved
mount / kind memfs {AppendOnly:false ReadDestructive:false ReadOnly:false Broadcast:false ObjectStore:false}
mount /scratch kind memfs {AppendOnly:false ReadDestructive:false ReadOnly:false Broadcast:false ObjectStore:false}
```

memfs claims nothing at any path. That is the point of it: every descriptor a
later plugin sets is read against a tree where none is set, so what the
descriptor changes is visible rather than assumed.

## What surprised me

**The reference implementation is defined by what it refuses.** memfs answers
`AsStreamer` and `AsTruncater` — a byte slice is trivially both — and refuses
`AsSymlinker`. A tree in memory has no links, so implementing them means
inventing their semantics: which verbs follow a link, what `Stat` of one says,
how a cycle ends. Whatever memfs invented would become what the conformance
suite asserts, and E2.2's `localfs` would then be read against an invention
rather than against the host disk, where links are native and the semantics are
already decided. The refusal is the deliverable; `localfs` is where link
coverage belongs.

**One mutex, not one per node.** A rename moves an entry between two parents and
a walk reads every node down a chain, so per-node locking would have to be taken
in an order neither operation knows before it starts. A single `sync.RWMutex`
over the tree is the honest answer for a structure this size, and the contention
test under `-race` is what says so.

**A settings map with nothing in it is still a boundary.** memfs takes no
settings, and the choice is between ignoring one it is given and refusing it.
Ignoring makes `{"root": "/tmp/nerve"}` — a `localfs` setting on a `memfs`
mount — a silent no-op. Refusing makes it a boot failure that names the setting,
which is the rule `config.fromFile` already applies one layer up.

**`Rename` needed a check that has nothing to do with renaming.** Moving a
directory into its own subtree detaches it from the root: the entries survive in
memory and no path reaches them. Nothing in the port mentions it, and a tree is
the only shape where it is possible.

**`OpenWrite` answers at open what it cannot answer at close.** The port says a
streamed write is not complete until `Close` returns nil, so the buffer commits
there. But a missing parent is knowable at open, and finding out after streaming
a payload into a buffer nothing will accept is a worse answer at a worse time.

## What I would do differently

Take `Remove` of a non-empty directory as the sentinel it is: `fs.ErrExist`
reads as "entries are still in it", which is true, but `ErrInvalid` reads as
"not a thing you can do to this path", which is also true. The port names four
sentinels and this case is between two of them. It was decided here, in the
first plugin, which means every later plugin now matches memfs rather than a
rule written down somewhere — E2.6 is where that becomes a shared decision, and
it should have been made there first.

## What I still do not understand

Whether `RemoveAll("/")` should empty the root or refuse. Emptying keeps the
verb's promise — everything beneath the path — and makes memfs resettable
between tests without rebuilding it. Refusing would keep the root as immovable
as `Remove` and `Rename` already treat it. The conformance suite will have to
pick one for every plugin, and a mount table means the root a plugin sees is a
mount point rather than the tree's root, which is an argument for emptying.

Whether `ModTime` needs a clock seam. `time.Now()` is enough to see a write
change it, but a plugin that has to prove ordering across two entries is one
scheduler hiccup away from a flake, and injecting a clock into every plugin is
the kind of ceremony that earns its place only once a second caller needs it.
