# E2.2 — localfs

`internal/adapters/outbound/localfs`: a host directory behind the ten verbs,
`Caps` and all three accessors. `cmd/nerved` registers it under the kind name
`localfs` with one setting, `root`, so a config document can now mount a disk
beside a tree in memory.

## What the pattern was

The second plugin, and the first that stores nothing itself. memfs holds the
tree; localfs holds only where the tree is, and the host does the storing and
the locking. There is no mutex in the package.

```
$ NERVE_CONFIG=nerve.json ./bin/nerved
mount / kind memfs {AppendOnly:false ReadDestructive:false ReadOnly:false Broadcast:false ObjectStore:false}
mount /disk kind localfs {AppendOnly:false ReadDestructive:false ReadOnly:false Broadcast:false ObjectStore:false}

$ curl -s localhost:9931/config | jq '.mounts[1]'
{"prefix": "/disk", "kind": "localfs", "settings": {"root": "/srv/nerve/disk"}}

$ NERVE_CONFIG=typo.json ./bin/nerved
nerved: mount "/disk" of kind "localfs": kind "localfs" root: stat /srv/nerve/disk-typo: no such file or directory
```

It runs the conformance suite and answers every case, including the four
symlink cases memfs skips: this is where E2.1 said link coverage belonged, and
it arrived without anyone inventing what a link means.

## What surprised me

**The suite asserted something no disk can do.** `Write moves ModTime forward`
compared two stamps and required the second to be later. A host stamps an entry
from a clock that advances in ticks — measured here at about a millisecond — so
two writes inside one tick carry the same time to the nanosecond:

```
0 18:25:15.815008124
1 18:25:15.815008124
2 18:25:15.816008155
```

memfs never showed it because `time.Now()` is fine-grained. The fix went into
the case rather than into localfs: it now writes until the clock has moved,
under a deadline, so a plugin that does not stamp its writes still fails. The
alternative — `os.Chtimes` after every write — would have made localfs report a
time the host never recorded, and said nothing about a file another process
wrote, which is the whole point of this kind.

**Only three errnos needed translating.** `os` already maps `ENOENT`, `EEXIST`,
`ENOTEMPTY` and `EACCES` onto the sentinels the port names. `EISDIR`, `ENOTDIR`
and `EINVAL` have no mapping and would have reached a caller as a bare errno, so
one helper turns them into `fs.ErrInvalid`. `Mkdir` is the exception that proves
it: a file in the way is `ENOTDIR` from the host and `fs.ErrExist` in the port,
so it is translated at the verb and not in the helper.

**A directory opens.** `os.Open` of a directory succeeds on a host disk and only
fails at the first read, so `OpenRead` stats the handle it just opened and
refuses there. A caller finds out from the verb it called, rather than from an
`io.Reader` that fails once.

**`OpenWrite` streams to a file beside the target and renames at `Close`.**
The port says a streamed write is not complete until `Close` returns nil, and a
disk is exactly where that matters: buffering the whole payload in memory the
way memfs does would defeat the reason a caller reached for a stream. The rename
is atomic, so a reader alongside sees the old content or the new one and never
half of either. The cost is visible: between `OpenWrite` and `Close` a
`.nerve-write-*` file is listed in that directory by `ReadDir`, where memfs
shows nothing.

**Containment is lexical, and it is a test rather than a comment.** Every path
is cleaned before it is joined to the root, so `/../secret` is `/secret` inside
the mount. The Forge constraint that one workspace cannot be seen from another
makes that a correctness requirement, so `TestNoPathClimbsOutOfTheRoot` spells
out the spellings.

**A link has to be read back in the mount's vocabulary.** `Symlink` writes the
host path of its target so the host resolves the link the same way this mount
does, and `Readlink` maps it back to a mount path. A target outside the root is
handed back as the host wrote it, because the mount has no name for it.

## What I would do differently

Take the landing rule to the conformance suite rather than solving it here. The
port promises `Rename` replaces `newPath` if it exists, and a host refuses a
file onto a directory and a directory onto a file, so `clearLanding` takes an
empty landing of the other kind out of the way first. No case in the suite
covers that pairing: memfs and localfs agree only because both were written to
the same sentence. It belongs in `vfstest` with the other rename cases, filed as
E2.6 follow-up.

## What I still do not understand

Whether the root should be created when it is not there. Refusing makes a typo a
boot failure that names the path, which is what a mount over somebody else's
disk deserves. Creating would make a fresh checkout run without an operator
laying out directories first, and every later plugin with a location setting
faces the same question — an object store bucket, a SQLite file.

Whether `elements` belongs in the core's vocabulary. memfs and localfs each have
their own copy of the path-cleaning helper, which is two and not yet three. The
third plugin decides it.
