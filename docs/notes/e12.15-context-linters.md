# E12.15 — the context-discipline linters

`containedctx` for "never store a `Context` in a struct" and `revive`'s
`context-as-argument` for "`ctx` is the first parameter", both named in
`.golangci.yml` alongside the E12.14 set.

## What the pattern was

Two of Tenet 4's five context rules are mechanically checkable, and each has
exactly one linter that checks it. The other three — deadlines propagate, every
goroutine has an owner and a way to stop, channels orchestrate while a mutex
holds state — have none, which is why E12.16 exists as a runtime check and
E12.17 as review plus a test.

## What surprised me

**`revive` runs its whole default set unless you name rules.** Enabling it for
one rule and leaving `settings.revive` empty pulls in `exported`, `var-naming`,
`package-comments` and the rest — a formatting opinion this repo already gave to
`gofmt` and `staticcheck`. Naming `context-as-argument` under `rules:` narrows
revive to that one rule, so enabling the linter enforces one tenet clause rather
than a style guide.

**`context-as-argument` needs `allowTypesBefore` or it fights the stdlib test
shape.** `func helper(t *testing.T, ctx context.Context)` is the idiomatic
signature and the rule flags it by default. The argument lists the three testing
types, so the rule applies to production signatures and leaves test helpers
alone without an `exclusions` entry keyed on `_test\.go$`.

**`containedctx` is the narrower of the two by a long way.** It fires on a
struct field, so a `Context` reaching a struct through an embedded type or a
`interface{}` field is invisible to it. It catches the direct spelling, which is
the one that gets written.

## What I would do differently

`contextcheck` and `noctx` were both on the shortlist and neither went in.
`contextcheck` flags a function that builds a fresh `context.Background()` when
an inherited one was available — close to "deadlines propagate", but it reports
against call graphs and its false positives land on legitimate detached work.
`noctx` demands a `Context` on HTTP calls, which is E12.17's territory and
belongs with the timeout rule rather than ahead of it. Adding either now would
mean tuning exclusions for a rule no code yet violates.

## What I still do not understand

Whether `containedctx` should be excluded in tests. It is enforced everywhere
today and no test stores a `Context`. A table-driven test whose case struct
carries a per-case context is a plausible shape, and the honest answer then is
probably a field of type `func() context.Context` rather than an exclusion.

## Evidence

Probed with a throwaway package holding both violations:

```
internal/ctxprobe/probe.go:7:2: found a struct that contains a context.Context field (containedctx)
internal/ctxprobe/probe.go:10:24: context-as-argument: context.Context should be the first parameter of a function (revive)
```

`func helper(t *testing.T, ctx context.Context)` in the same package's test file
produced no revive finding. `golangci-lint config verify` exits 0, and
`golangci-lint run ./...` reports 0 issues with the probe removed.
