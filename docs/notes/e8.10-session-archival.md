# E8.10 — Session archival

A conversation that has gone cold has its older turns moved aside and a summary of
them retained on the session. Two pieces:

- `session.Store` gains `Archive` and `Archived`. `Archive` moves every message up
  to a sequence into the session's `ARCHIVE` directory and writes the summary into
  the `SESSION` record; `Archived` reads those messages back.
- `internal/core/archive` composes the store with `llm.Summariser`: read the
  transcript, take everything but the last `keep` turns, summarise through the
  gateway, archive through the last cold sequence.

The ticket's acceptance is one test in each layer:

```
$ go test ./internal/core/archive/ ./internal/core/session/ \
    -run "AColdTranscriptIsMovedAsideWithASummaryRetained|ArchivedSequencesAreNeverHandedOutAgain" \
    -v -count=1 | grep -E '^(--- |    --- )'
--- PASS: TestAColdTranscriptIsMovedAsideWithASummaryRetained (0.00s)
--- PASS: TestAColdTranscriptIsMovedAsideWithASummaryRetained (0.00s)
    --- PASS: TestAColdTranscriptIsMovedAsideWithASummaryRetained/keyspace (0.00s)
    --- PASS: TestAColdTranscriptIsMovedAsideWithASummaryRetained/tree (0.00s)
--- PASS: TestArchivedSequencesAreNeverHandedOutAgain (0.00s)
    --- PASS: TestArchivedSequencesAreNeverHandedOutAgain/tree (0.00s)
    --- PASS: TestArchivedSequencesAreNeverHandedOutAgain/keyspace (0.00s)
```

## What the pattern was

`archive.Archiver` is `commit.Committer` again: a core package holding a store and
one narrow model port, refusing a nil port at construction because that is what the
gateway answers when nothing in the chain serves the verb. The stability policy is
the gateway link's, so a second stage reading a transcript through a model needed no
second timeout, breaker or retry.

The store half is the pattern the store already had — every path through
`Scope.Path`, every verb asked over `memfs` and over `kvfs`, `fs.ErrInvalid` for
what cannot be, `fs.ErrNotExist` for what is not there. The archive is a directory
inside the session, so on a tree it is a subdirectory and on a keyspace it is a
deeper prefix, and nothing above the port can tell.

## What surprised me

**Archiving broke `Append`, and the break was silent.** `Append` took the next
sequence from the highest message file present. Move every message into the archive
and the highest present is none, so the next turn is numbered one again — and there
is already a message one, in the archive, saying something else. Nothing errors:
the write lands at a free path, and the session quietly holds two first turns that
a restore would have to choose between. The fix is that the record carries how far
the archive reaches and `Append` counts past it, which is what makes "a sequence is
never handed out twice" a property rather than a consequence of never having
archived anything. The test that catches it archives the whole transcript, because
that is the only shape where the bug shows.

**The order of the two writes is the whole recovery story.** `Archive` writes the
record and then moves the messages. Interrupted that way it leaves cold messages
still in the transcript, and running the same call again finishes the job.
Interrupted the other way round it leaves messages in the archive under sequences
the record does not know are taken, and the next append hands one of them out a
second time — the same defect as above, arrived at by crashing rather than by
design. There is no transaction here and there does not need to be; there is an
order in which a partial failure is recoverable, and one in which it is not.

**The summary has to cover the archive, not the increment.** A session archived
twice would otherwise end up retaining a summary of its second cold half and
nothing at all about its first, while the archive holds both. So the archiver
shows the summariser the summary the session already carried alongside the newly
cold turns, and the store refuses a `through` below what is already archived. Both
of those exist to keep one sentence true: what `Session.Summary` says stands for
everything in `ARCHIVE`.

**E8.1 predicted a `Put` over the metadata and that would have been the wrong
verb.** The note left on E8.1 said retaining a summary is a metadata write and
should land as a `Put`-shaped verb over the record. A general metadata write is
also a verb that can change `Created`, or rewrite the metadata a session was opened
with — and none of that is what archiving needs. `Archive` writes the record itself,
which is the only write in the package to a file it has already written, and the
record staying its own file is still what makes that free of the transcript.

## What I chose not to build

No restore. `Archived` reads the cold messages back, which is what makes the move
distinguishable from a deletion, and nothing moves them into the transcript again.
E8.9 is the ticket that decides what restore means for a memory, and a session
restore invented before it would be a second answer to the same question.

No policy about when to archive. `Archive` takes how many turns to keep and is
called by whoever decided; nothing here watches a session's length or its age. The
caller that runs it on a schedule is E8.2's context builder or a job above it, and
what it should watch is not visible yet.

No paging over a transcript. `Get` still reads every message that has not been
archived, which is now bounded by what the archiving caller keeps rather than by
the length of the conversation. That was the argument for `Since(seq)` on E8.1 and
it is weaker now than it was.

No route and no wiring in `main`, for the reason `session.Store` and
`commit.Committer` are not wired either: E8.2 is where a transport first sees any
of this.

## What I still do not understand

Whether the archive should be one directory per archival round rather than one
directory holding every cold message. One directory keeps the sequences unique and
makes `Archived` a single listing, and it loses the boundaries — a caller cannot ask
what the third archival moved, or which summary covered which turns, because only
the newest summary survives. That is exactly the shape E8.8's as-of queries want for
memories, and I do not know yet whether a session wants it too or whether a session
is the one thing that only ever needs its current state.

Whether a summariser that answers with an empty string should be refused where it
is now. The store refuses it, because an archive with no summary is unreachable to
every caller that only reads the session — but the endpoint that returned it is the
thing that is broken, and the error a caller sees names the archive instead.
