# E6.4 — the levels a document has

`ingest.Level` is one rung of the ladder a caller escalates up — the sidecar a
summary is written under and how many sentences that rung is allowed to be — and
`ingest.Levels` is the ladder a build has unless composition passes another: L0
`abstract`, L1 `overview`, L2 `detail`. `ingest.Summariser` is the port that
says what a document is about in at most the sentences it is given, and
`Summarisation` is the stage that reads the words extraction left and writes one
sidecar per rung. `termsum` is the laptop's summariser.

The acceptance is that every ingested document has all three, and it is asserted
at both ends — that each rung asks for its own budget, and that the abstract is
what the document is about rather than what it opens with:

```
$ go test ./internal/core/ingest/    # with every rung asking for the same budget
--- FAIL: TestEveryIngestedDocumentHasAbstractOverviewAndDetail
    summarise_test.go:56: overview = "1: A FIRST DRAFT", want "5: A FIRST DRAFT"
    summarise_test.go:56: detail = "1: A FIRST DRAFT", want "20: A FIRST DRAFT"

$ go test ./internal/core/ingest/    # with a document nothing could read failing the run
--- FAIL: TestSummarisationLeavesADocumentNothingExtracted
    summarise_test.go:86: Run: handle "resources/ada/hunt/diagram.png/meta.json":
        ingest "diagram.png": stage "summarise": read "text" of resource
        "diagram.png": read "/ada/hunt/diagram.png/text": file does not exist

$ go test ./internal/adapters/outbound/termsum/    # with the summary taken from the front
--- FAIL: TestTheAbstractIsTheSentenceTheDocumentIsAbout
    termsum_test.go:48: abstract = ["The office closed on Wednesday and stayed
        closed for a week."], want "The flood defences depend on the pumps, and
        the pumps depend on maintenance nobody funded."
```

## What the pattern was

`library.Matcher` and `termmatch`, one altitude down and for the same reason:
the second implementation is nameable — a model behind E7.1's gateway — so the
thing that cannot be done on a laptop sits behind a port and the laptop's answer
is a package registered at composition. The stage holds a `Summariser` and
learns neither.

What is new here is that **the ladder is data**. Three rungs could have been
three methods, three constants, or a `switch` on a level; they are a slice of
`Level` passed to the stage, so a fourth rung is a line at the composition root
and a different ladder is configuration. Nothing in the stage counts three, and
the test that proves it asks for a rung the package does not name:

```go
extracted(t, b, budgets{}, ingest.Level{Kind: "headline", Sentences: 1})
```

That is the repo's thesis at the smallest scale it has yet appeared: one
interface, a list of self-describing things, and a new kind that needs config
rather than code.

The stage reads the `text` sidecar rather than the content, which is what
E6.3's `Derived`/`SetDerived` pair was general for. The format is over by the
time this runs. A stage that read the content would be a second thing in the
pipeline that has to know how to parse a PDF.

## What surprised me

**The do-nothing branch is the pipeline's rule, not extraction's.** E6.3 found
that a format this build cannot read must not fail the run, or one PNG stops
every job behind it forever. Summarisation has the same branch for the same
reason — a document with no text sidecar is left alone — and the second
occurrence is the one that shows it is a property of a retried queue rather
than a fact about formats. Any stage after this one will have it too.

**Weighting a word by how much of the document says it removes stopwords with
no list of stopwords.** `termsum` scores a sentence by the weight of its
distinct words, and a word weighs how often it is said discounted by how much
of the document says it: `frequency × log(sentences / holding)`. A word in
every sentence weighs exactly zero, which is what happens to "the" without
anybody naming it, in any language. `termmatch` deliberately uses
`log(1 + cards/holding)`, which never reaches zero, because a library of one
card has to stay answerable — here reaching zero is the whole point, and the
same formula with the smoothing taken out does a stopword list's job in one
line.

**That weighting is flat on a short document.** A word said once in each of `k`
sentences out of `N` weighs `k·log(N/k)`, which for `N = 4` is the same at
`k = 1` and `k = 2`: on a four-sentence document the sentence about the subject
and an aside made of words used nowhere else score alike. It separates only once
a word can be frequent without being everywhere, which is also the only length
at which a summary is worth having. The test document is twelve sentences
because four could not tell a working summariser from a broken one.

**Sentences come back one to a line.** Joined into a paragraph, two sentences
the document never put together read as prose it never wrote — the summary
claims a continuity that is not in the source. A line break is the cheapest way
to say "these are sentences from the document" rather than "this is a passage".

## What I would do differently

Take the ladder from config rather than from a package-level var. It is a var
because the composition root does not build a pipeline yet — E6.1 and E6.2 left
`ingest.New` called only by tests — so `Levels` is the only ladder anyone has
run, and the budgets are not observable at `/config` with everything else that
is operationally interesting. The seam is right; the layer that would fill it
does not exist, and adding config for a pipeline nothing composes would be a
layer that cannot be run.

## What I still do not understand

**Whether nesting is a property of levels or of this summariser.**
`termsum`'s abstract is always among its overview's sentences, because both are
the top of one ranking, and that is asserted. An abstractive summariser has no
such property: asked for one sentence and then for five, a model writes six
different ones. E6.5's caller escalating from L0 to L1 may come to rely on
something only one implementation has, and the port does not promise it.

**Whether L2 earns its rung.** Twenty sentences of a short document is the
document, and the ladder collapses to two rungs and a copy. It is right for
something long, and nothing this ingests yet is.

**Whether a budget in sentences survives a model.** It is what an extractive
summariser selects by and what a model can be told, but what a model actually
bounds well is words. Which unit the port should carry is E7.1's answer.

**What a sentence is in a document that is not prose.** A table lifted out of a
PDF, or a code file uploaded as text, has no sentences; this reads its lines as
sentences and scores them, and what comes back is the lines that use the file's
own vocabulary most. That is not wrong so much as not meant.
