# E3.4 — Work bus

The consuming end of `queuefs`. There is no new package and no new transport:
the bus is the queue mount seen from both sides.

```
producer   Write /queue/jobs/index/document/42   → journal, then relay → exchange
worker     Listener says "index/document/42"     → Read /queue/jobs/index/document/42
```

Three things landed, all in `internal/adapters/outbound/queuefs`:

| Piece | What it is |
|---|---|
| `Listener` | The `Broker` port's other end. One verb: call me back with a key. |
| `Consumer` | The shipped `Listener`: a durable RabbitMQ queue bound to the exchange the relay already publishes to. |
| `Worker` | Claims what it is told about, through the mount table, and hands it to a `Handler`. |

Publishing needed nothing at all. It was already `Write`.

## What the pattern was

**A second port over one adapter, for the second consumer of it.** `Outbox` is
`Journal` seen by the relay; `Listener` is `Broker` seen by a worker. Neither is
a new abstraction over the thing — it is the same thing, described in the
vocabulary of whoever holds it. A relay has no business consuming and a worker
has no business publishing, so neither gets a method for it.

**The claim is what settles who does the work.** Two workers told about the same
key both call `Read`; a read-destructive mount hands a message back once, so one
gets a body and the other gets `fs.ErrNotExist` and moves on. Competing
consumers needed no lock, no lease and no code — the descriptor already said it.

**Two records, so two crash windows, and each is covered by the thing that
kept it.**

| Crash | Kept by | What happens next |
|---|---|---|
| Recorded, broker never told | the journal | the next write carries it, and the worker hears about it then |
| Told, never claimed | the broker | the delivery was never acknowledged, so it comes back to the next worker |
| Claimed, handler failed | nothing | the run ends and says why |

The third row is deliberate and is the price of a destructive read. Ending the
run is the loud version of it: carrying on would lose a message quietly, and
putting it back would need a claim that expires to stop a message nobody can
handle going round forever.

**The worker claims through the mount table, not through the journal.** It holds
`vfs.FileSystem` and a mount prefix, so a claim is bounded by that mount's
timeout, retried under its policy and stopped by its breaker, exactly like every
other call into it. A worker that reached for `Journal` would have been a second
path into the same store with none of that on it.

## What surprised me

**A racy test was pointing at a hole in the design.** `Listen(ctx, pattern,
notify)` reads well and was wrong: it binds the queue on the first call, so a
queue that has never been listened to hears nothing published before then. The
crash case could not be written without a sleep or a pre-bind — and the reason
was that a subscription is a standing arrangement with the broker, not a
parameter of one call. The pattern moved to `DialConsumer`, the port lost an
argument, `Worker` lost one too, and the test became ordered. What a signature
should carry follows from the lifetime of the thing behind it.

**A routing key is a route, not a name.** E3.1 turns `/jobs/index/document/42`
into the topic `index.document.42` so a consumer can bind to `index.#`. Read
back the other way, `a.b.1` is `a/b/1` — and a key with a dot in an element
becomes a different key. The key travels as the AMQP message id instead, which
is exact, and the topic stays what it is for.

**Manual acknowledgement is about the notification, never the message.** The
body was never at risk: it sits in Postgres until someone claims it. What an ack
protects is the much smaller thing — knowing there is something to claim. Acking
after the handler returns costs nothing and turns "a worker died before
claiming" from a message that waits for a backfill into a message the broker
hands to the next worker.

**"Do not build a second distribution abstraction" was a constraint that wrote
half the code by deleting it.** There is no `Publisher`, no envelope, no message
type, no dispatcher and no registry of handlers. A `Handler` is a func. The bus
is two verbs that already existed pointed in opposite directions.

## What I would do differently

Write the crash case first. Both design corrections in this increment — binding
at dial, and the key travelling as the message id — came out of trying to make
the crash simulation deterministic against the real broker, not out of reading
the code. The offline fake agreed with whatever I built, again.

## What I chose not to build

**Redelivery after a claim.** No visibility timeout, no dead-letter path. A
handler that fails ends the run, and the message it was given is gone. E3.1 left
claims that expire out for the same reason and this is the first place the cost
of that is visible.

**A worker in `cmd/nerved`.** There is no handler to run. Wiring one now would
mean inventing work for it and a config section describing which mount, which
pattern and which queue name — before anything asks. E3.5's `WriteObserver` is
the first thing that produces work with a consumer to match, and that is when a
worker earns a place in the composition root.

**Concurrency inside a worker.** One message at a time, prefetch one. Two
workers is two processes competing on one durable queue, which is what the claim
already makes safe.

**Anything about ordering.** A topic exchange and competing consumers say
nothing about the order work is done in, and neither does this.

## What I still do not understand

Whether a worker should be reachable through the tree. Everything else in Nerve
is a mount; a worker is a thing the composition root holds. That may be right —
it is a caller, not a store — or it may be the next place the uniform interface
should have reached.

Whether ending the run is still the right answer to a failing handler once
something is restarting workers. It is right when a person is watching. Under a
supervisor it becomes a crash loop that eats one message per restart, and the
answer to that is a claim that expires, which is a bigger change than it sounds.

case is the one the fake can only model: a worker is told there is work, its
