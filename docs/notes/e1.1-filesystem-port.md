# E1.1 — the FileSystem port

The ten verbs — create, mkdir, remove, remove_all, read, write, read_dir, stat,
rename, chmod — as one interface in `internal/core/vfs`, with `FileInfo` as the
thing `stat` and `read_dir` return.

## What the pattern was

A port in the core's own vocabulary, satisfied later by every storage kind:
disk, object store, queue, vector index. Nothing else exists yet, so the whole
increment is a shape and the argument for it.

## What surprised me

Three decisions that looked like detail turned out to be the design.

**Mode is not a creation parameter.** `os.Create` takes one, so `Create` and
`Mkdir` and `Write` all wanted one. But a queue has no permission bits, and a
vector index has none either — every one of them would have had to invent a
value to ignore. `Chmod` already exists as its own verb, so mode belongs there
alone. The host filesystem is one plugin, not the model.

**`FileInfo` is a struct, not an interface.** `fs.FileInfo` carries `Sys() any`,
which is an invitation to type-assert back to the concrete implementation — the
exact move this repo's settled decision forbids. A struct has no such door: what
a plugin has to say about an entry, it says in fields.

**`Mkdir` creates parents.** One verb, and the fallacy that latency is zero
means a caller must not loop over remote calls to build a path.

## What I would do differently

The test asserts the interface has exactly these ten method names. It reads like
a tautology and is not: it is the only mechanical guard on the settled decision
that a new capability arrives as a descriptor or an accessor, never as an
eleventh verb that every plugin then has to answer.

## What I still do not understand

Whether `Read` returning `[]byte` survives contact with E2.4's object store,
where an entry can be larger than memory. The `Streamer` accessor (E1.3) is
where that is supposed to go, but nothing has tested the seam yet.

Whether `Create` earns its place once plugins exist. With stateful open handles
skipped (E1.7), `Create(path)` and `Write(path, nil)` differ only in intent. The
roadmap fixes the verb, so it stays; the first plugin that has to implement both
will say whether that was right.
