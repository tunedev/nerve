# E12.1 — Layered config

Four layers — defaults, a JSON file, the environment, flags — folded in that
order in `internal/config`, with `Load` returning the zero `Config` alongside
any error so a caller that ignores it boots on nothing rather than on something
plausible.

## What the pattern was

Each layer is a `func(Config) (Config, error)` and `Load` is the fold over
three of them on top of `Defaults()`. "Later wins" is then a property of the
slice order rather than a rule anything has to enforce.

## What surprised me

**Three of the four layers already do the right thing for free.** `json.Decode`
into an already-populated struct writes only the keys the document names, so the
file layer inherits "absent keeps the layer below" from the stdlib. A flag whose
default is the value resolved so far changes nothing when it is not passed, so
the flag layer needs no `Visit` over what the operator actually typed — and the
usage text ends up showing the values that would really be used. Only the
environment layer needed writing, and only because `os.Getenv` cannot tell unset
from empty; `LookupEnv` can.

**The config file path cannot be a flag.** The file layer sits below the flag
layer, so a flag naming the file would have to be read before the layer it
overrides — the two-pass parse every config library eventually grows. An
environment variable sits at the right height and costs nothing, so `NERVE_CONFIG`
names the file.

**Rejecting an unknown key is most of the value.** A misspelled setting that is
silently ignored is exactly the failure "invalid config fails at boot" is about,
and it is one `DisallowUnknownFields` call.

**One canonical spelling per setting.** `log-level` is the flag name and the JSON
key, and `NERVE_LOG_LEVEL` is derived from it. The field table carries the name
once; three spellings kept by hand would drift.

## What I would do differently

Nothing yet. `errors.Join` in `Validate` means one boot reports every problem,
which matters more than it sounds: the alternative costs an operator one restart
per mistake.

## What I still do not understand

Whether every setting stays a string. Parsing belongs to the adapter that uses a
value, but a duration or a port number validated at boot rather than at first use
is the whole point of failing early, and `Validate` currently gets at that by
checking shape (`postgres-dsn` parses, names a host) without producing the parsed
value. If a second consumer wants the same parse, that duplication is the signal
to move it.

Whether `Sources` survives E1.5. Mounts arrive by config there, which is a list
rather than a scalar, and a list has no obvious meaning for "later wins" —
replace the whole list, or merge by mount point. That ticket decides it.
