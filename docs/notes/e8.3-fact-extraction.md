# E8.3 — Extraction of structured facts with priorities

A committed session becomes typed memories. Four pieces:

- `llm.FactExtractor` — a second capability on the gateway, reached through
  `AsFactExtractor` and routed exactly as `Summariser` is.
- `internal/core/memory` — the append-only log of typed, ranked facts a workspace
  keeps, on the one FileSystem the mount table presents.
- `internal/core/commit` — reads a transcript, extracts through the gateway, writes
  the result. Where E8.4 to E8.7 add their stages.
- `internal/adapters/outbound/cuefact` — the laptop's extractor: cues, not a model.

The ticket's acceptance is one test in each of the three layers:

```
$ go test ./internal/core/commit/ ./internal/core/memory/ ./internal/adapters/outbound/cuefact/ \
    -run "ATranscriptBecomesTypedMemories|AMemoryIsATypedRankedFact|ACuedSentenceIsATypedRankedFact" -v -count=1
--- PASS: TestATranscriptBecomesTypedMemories (0.00s)
--- PASS: TestAMemoryIsATypedRankedFactNamingItsSession (0.00s)
    --- PASS: TestAMemoryIsATypedRankedFactNamingItsSession/keyspace (0.00s)
    --- PASS: TestAMemoryIsATypedRankedFactNamingItsSession/tree (0.00s)
--- PASS: TestACuedSentenceIsATypedRankedFact (0.00s)
```

## What the pattern was

`memory.Store` is `session.Store` again: hold the tree and a root, take a
`workspace.Scope` per call, derive every path through `Scope.Path`, know no plugin,
refuse user scope, take the clock as `func() time.Time`. One file per memory named
by its sequence, so nothing already written is read back and rewritten — the same
reason a transcript is one file per message. Every verb is asked over `memfs` and
over `kvfs`.

The gateway capability is `Summariser` copied line for line: a port on `Provider`
returning a narrow interface or nil, an accessor on `Gateway` that resolves the
chain once and answers nil when nothing serves it, and a routed verb underneath.
The stability policy is the link's rather than the capability's, so the second
capability needed no second timeout, circuit or retry — which is the whole argument
for the chain being the one path a model call takes.

## What surprised me

**Priority stops being useful the moment it is derived from the kind.** The first
cut ranked an instruction High and a preference Normal, and that is not a priority,
it is the kind spelled twice — a caller sorting by it learns nothing it could not
read off `Kind`. The hedge rule is what gives it independent signal: "always run the
tests" and "I think we should always run the tests" are the same kind of claim and
not the same claim, and one rung is the difference. That also decided that `Low`
exists at all, because a hedge has to have somewhere to go.

**Two `Fact` types with a mapper between them, on purpose.** `llm.Fact` and
`memory.Fact` have the same three fields and there is a six-line mapper in `commit`.
The instinct is that one of them is redundant. It is not: `llm` speaks only its own
vocabulary — `Summarise` takes a string and a count — so how a workspace stores its
memories is not part of the contract with a model endpoint, and a hosted provider
added later cannot reach the shape of what is already on disk. The mapper is the
boundary, and it is where a priority an endpoint invented is left off the scale
rather than filed under the nearest rung.

**The priority is stored by name and not by number.** `Low`, `Normal`, `High` are
`iota` values, and writing those to a file makes this package's ordering part of the
stored format: inserting a rung between two of them would silently re-rank every
memory already written. A name off the scale fails the read rather than decoding to
whatever it sorts next to.

**A batch is validated whole before any of it is written.** A commit that stored
three facts of five and failed leaves a workspace holding some of what a
conversation said with no record of which half, and E8.7 would later reconcile
against a memory that is half a conversation. Validating first is what makes a
failed commit a commit that did not happen.

## What I would do differently

`termsum.Sentences` is now exported so `cuefact` can use it, which is one adapter
importing another. The alternative was a second sentence splitter that disagrees
with the first about where a fact ends, which is worse — but the honest home for it
is a small text package neither adapter owns, and the second caller is the moment
that becomes obvious rather than speculative. It is one move away.

## What I chose not to build

No dedup, no consolidation, no reconciliation. Committing the same session twice
writes its facts twice, which is E8.5's whole ticket, and `Commit` says so.

No route and no wiring in `main`. `session.Store` is not wired either, for the same
reason: E8.2 is where a transport first sees any of this. What is wired is the
provider kind, so the banner reports `extract` on a laptop with no model.

No `Get`, `Delete` or filter on `memory.Store`. `Add` and `List` are what a commit
and E8.2's context need; archive and supersede are E8.9 and want a shape this
ticket cannot see yet.

No entity extraction. E7.4 is a different port with a different output, and putting
both behind one accessor now would be guessing at what it needs.

## What I still do not understand

Whether `Source` should name the session or the message range inside it. Naming the
session is enough to delete a workspace's memories with the conversation that
produced them, and it is not enough for E8.7 to show a user the turn a contradicted
fact came from. The sequences exist on the transcript; nothing carries them across
yet, because the extractor port deliberately does not see them — and I do not know
whether reconciliation wants the turn or just the session it was in.

Whether `cuefact` is a floor or a trap. It works, and every fact it returns is a
sentence the user actually wrote, which is a strong property. But a cue list is
exactly the kind of thing that quietly becomes the specification: the next ticket
that finds extraction thin will be tempted to add cues rather than to configure a
model, and there is nothing in the code that says which of those is the fix.
