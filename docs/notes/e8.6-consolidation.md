# E8.6 — Commit: consolidation into narratives

Related facts merge. Four pieces:

- `llm.FactConsolidator` and `llm.Narrative` — a fourth capability on the gateway,
  reached through `AsFactConsolidator` and routed exactly as `FactExtractor` is.
- `internal/core/consolidate` — the stage: read what the workspace believes, ask
  the endpoint which of it says one thing, write each narrative through
  `memory.Store.Supersede`.
- `commit.Committer` — holds the consolidator and runs it between the write and
  the archival. `Result` gains `Narratives`.
- `internal/adapters/outbound/termfold` — the laptop's consolidator, merging by
  shared vocabulary within a category.

## What the pattern was

E8.5's note says the ticket that reads as a pipeline stage was not one, because
the rule belonged to the log. This one is the opposite case and it is worth
being able to tell them apart. Dedup is a property of a write — no writer may
add a claim the log already holds — so it lives where writes happen. Consolidation
is a decision about the whole of what a workspace believes, made by an endpoint,
producing writes. It has a lifecycle of its own, it will be a route in E8.9, and
`archive` is the precedent: a stage package that `commit` composes.

`dedup.go` already named this seam before the stage existed: "Deciding whether two
sentences mean the same thing is a model's judgement and belongs to consolidation
and reconciliation." Dedup catches a claim restated word for word. Everything past
that — a paraphrase, a claim that narrows another — is here.

## The narrative names positions, not facts

`Narrative` answers with the positions of the facts it merged, the way `Embedder`
answers one vector per text in the order it was given. The caller holds the
memories those positions came from, so it can name what the narrative replaces.
An endpoint that answered with sentences would leave the stage matching text back
to memories to work out what it had been told to supersede — and a model that
reworded one of them slightly would break the match silently.

It carries no priority. Rank is derived by the stage from what was merged, taking
the highest: a narrative merging what a user said never to do is still what they
said never to do, and an endpoint that ranked its own sentence could demote it
into the half a caller with limited room drops first.

## Two kinds of bad answer, told apart

The stage sorts what an endpoint says into two piles, and the split is the only
real judgement in it.

- **Broken** — a position that was not in the batch, one named twice, a memory a
  second narrative already claimed, a narrative with no body. The answer is about
  something other than what was asked, so nothing is written from any of it.
  `fs.ErrInvalid`.
- **Declined** — a narrative naming one fact, or one mixing two categories. The
  endpoint proposed something this stage does not do. It is passed over and the
  rest of the run stands.

Refusing the second pile as well was the first draft. It is wrong: a model that
keeps proposing a cross-category merge would permanently block that workspace's
archival, which is a failing dependency becoming a failing system. Declining
degrades in parts instead, and the log is unchanged either way.

The one-fact rule is not fussiness. A narrative merging one memory would supersede
it with a rewording of itself, and the next run would do it again — a commit that
rewrites the log forever.

## Ordering, and why archival still runs last

Extraction, then the write, then consolidation, then archival.

Consolidation goes after the write because what it merges is what the workspace
believes, and that is not complete until this conversation's facts are in it. A
commit interrupted between them leaves the facts standing separately: a workspace
that answers with more sentences than it needs, which the next run merges. The
other order would weigh the old beliefs against a conversation that had not been
read yet.

It goes before archival because archival is the destructive stage and E8.4's
reasoning has not changed: a transcript reduced on behalf of work that did not
happen loses what the cold half said, and nothing recovers it.

## One call, not one per category

The whole believed set goes to the endpoint in one call. Which facts are related
is the judgement being asked for, so a caller that pre-grouped them by category
would have made it already — and a call per category pays the round trip once per
kind for a judgement the endpoint could make in one look. The category rule is
then held on the way back, where declining costs nothing.

## termfold, and what it is honestly not

Without a laptop-local consolidator, `gateway.AsFactConsolidator()` is nil on a
build with no Ollama, `consolidate.New` refuses, and `commit.New` refuses after
it — the whole memory pipeline would need a model to exist at all. cuefact was
added with E8.3's extraction for exactly this reason, so termfold is the same
move: `TestTheLaptopChainRunsTheWholeCommitPipeline` is the plane test for the
committer, and it now asserts all three capabilities off one local chain.

termfold merges facts of one category whose bodies share at least 0.4 of the words
between them, transitively, and writes the narrative by joining their own sentences
with "; ". It reads shared words, not meaning, so what it catches is a claim and
the same claim narrowed — "prefers tabs" with "prefers tabs in Go". A paraphrase
is not caught and cannot be: "likes tabs" shares one word in three with "prefers
tabs", which is exactly what "prefers dark mode" shares with it, so no threshold
keeps one and drops the other. That is the line where a model earns its place, and
the endpoint behind it is a line of config. The threshold is a setting because how
alike two sentences must be before a workspace stops saying both is an operator's
judgement.

## What surprised me

That consolidation converges without anything in the code arranging for it. The
run after a merge is shown the narrative and not what it merged — `Current` omits
superseded memories — and a narrative shares no distinctive vocabulary with
anything left, so it merges with nothing. The temporal work from E8.8 is doing
that, the same way E8.5's note found it doing dedup's.

## Deliberately not done

A fact restating a memory that a narrative superseded is written again. Dedup
indexes only currently believed memories, and after consolidation the original
claims are not among them, so the same sentence in a later conversation becomes a
new memory that the next consolidation merges into a new narrative. It converges
rather than growing without bound, but the log carries the churn. Reconciling a
new fact against a narrative that already contains it is E8.7's ground, not this
one's.

Nothing writes narratives except a commit. The lifecycle route that consolidates
on demand is E8.9, and the stage is already shaped for it: `Consolidate` takes a
scope and a source and knows nothing about sessions.
