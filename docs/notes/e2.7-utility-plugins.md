# E2.7 — The utility plugins

Six kinds that store nothing: `hellofs`, `heartbeatfs`, `serverinfofs`, `devfs`,
`httpfs`, `proxyfs`. Each mounts from config and answers `stat`, which is all the
ticket asked for; what they are actually for is being the awkward cases the five
storage kinds are not.

```
$ go test ./cmd/nerved/ -run TestEveryUtilityKindMountsAndAnswersStat -v | tail -2
--- PASS: TestEveryUtilityKindMountsAndAnswersStat (0.00s)
PASS
$ go test ./internal/adapters/outbound/proxyfs/ -run TestConformanceOverLocalfs -v | grep -c '^    --- PASS'
61
```

## What the pattern was

**Four of the six are one plugin.** `hellofs`, `heartbeatfs`, `serverinfofs` and
`devfs` all answer a fixed set of names whose content is computed at the moment
somebody reads it, so `internal/adapters/outbound/synth` holds that shape and
each kind is the map of entries it wants:

```go
func New(message string) *synth.Tree {
	return synth.NewTree(map[string]synth.Entry{Greeting: synth.Fixed(message)})
}
```

The tree is read-only at every path and says so, which is what makes the
conformance suite stop asking it to store and start asking it to refuse. Six
cases run against each of them instead of the sixty-one a read-write tree
answers, and the six are the ones that mean anything.

**`devfs` is the one that bends.** Its sink takes writes and keeps nothing while
the two sources beside it refuse the same verb, so it overrides `Write` and
`Capabilities` for that one name and inherits the refusals for everything else.
That is capability varying inside a single mount, which is the case E1.2's
descriptors exist for and which no storage kind had yet produced.

**`proxyfs` is where the settled decision gets its demonstration.** A proxy is a
dispatcher, so a caller holding one and writing `fsys.(Streamer)` interrogates
the proxy and gets nothing however well the plugin behind it streams. Forwarding
the accessors is not optional, and the suite is what says the forwarding is
complete: run over `localfs`, which answers all three optional verb sets, all 61
cases pass at names the target never sees. Over `memfs` it is 57, the four
skipped being the link verbs `memfs` does not answer.

**`httpfs` claims the object-store descriptor**, which is the honest reading of a
URL space: names are prefixes rather than a tree, and an origin has no listing to
answer `ReadDir` with. Claiming a tree would have promised a walk that cannot be
done.

## What surprised me

**A read-only plugin failed a case that had nothing to do with being read-only.**
`A new filesystem holds nothing` was gated on `tree` alone, and `hellofs` holds a
greeting. The gate was hiding an assumption: the case is not about emptiness, it
is about the suite being handed a world it controls. A mount whose content is the
plugin's did not start empty for the suite's benefit, so the gate is now
`needs(writable, tree)`. No coverage was lost — every plugin the case already ran
against is writable.

**A composed plugin gets wrapped twice unless you split the registry's build.**
`Registry.Build` puts the timeout, breaker and retry round every plugin it
returns. A proxy built its target through the same method, so a single call was
retried by two layers — attempts times attempts against a dependency already
failing, which is the exact multiplication Tenet 3 names. The fix is `Plugin`,
which is `Build` minus the wrappers, and `Build` is now one line over it. The
outer mount is wrapped on the way into the table; the target is not wrapped at
all.

**The descriptor vocabulary has no word for a sink.** `/dev/null` accepts content
and keeps none. `ReadOnly` would be a straight lie — the write succeeds — so it
claims the zero value, a plain read-write path, and the doc comment carries the
inaccuracy that is left. Adding a sixth descriptor for one entry in one plugin
would have been worse.

## What I would do differently

Give `synth.Entry` a way to say when its content changed from the start. I added
`Changed` for `heartbeatfs` after writing `ModTime` as "when the mount came up"
for everything and finding that a heartbeat whose `ModTime` never moves is a
heartbeat nobody can watch. It is two lines; the point is that "computed content"
and "fixed timestamp" were never going to be consistent, and I wrote the second
one first.

Name `proxyfs`'s settings before writing the factory. `target_kind` and
`target_prefix` are prefixed because the rest of a proxy's settings belong to the
kind behind it and pass through untouched; `kind` and `prefix` would have
collided with a target kind that wanted either word.

## What I still do not understand

Whether the pass-through settings should read back redacted. A proxy declares
only its own two settings public, so a `localfs` root behind a proxy is hidden
where the same root on a direct mount is shown. Safe, and inconsistent: the same
value reads back two ways depending on how it was mounted. The alternative is for
a proxy to ask the registry what the target kind declared, which means `Public`
learning about nesting — more surface than the inconsistency costs today, but the
inconsistency is real and an operator will hit it.

Whether `httpfs` should follow redirects, and whether a mount that does can still
claim containment. It follows them now, because that is `http.Client`'s default
and turning it off is its own decision. A 302 to another origin means a mount
answers for a host the config never named.
