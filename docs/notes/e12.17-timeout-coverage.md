# E12.17 — Timeout coverage on every outbound call

`internal/core/vfs/coverage_test.go` walks the port for every verb that takes a
context, sends each one through a mount table the registry built to a plugin
that never answers, and requires `context.DeadlineExceeded` back. The verb list
is read off the port by reflection, so it cannot fall behind the port.

## What the pattern was

Two assertions rather than one, because "every outbound call is bounded" is two
claims. `TestNoOutboundCallOutlivesItsBound` is the property; it can only speak
about verbs it knows to send. `TestEveryVerbThatSendsIsCovered` is the closure:
it reflects over `FileSystem`, `Symlinker`, `Streamer` and `Truncater`, splits
the methods by whether they take a context, and requires the sending half to be
exactly what the first test drives and the silent half to be exactly the four
discovery methods. A verb added to the port fails the second test the moment it
exists, before anyone has to notice it was left unbounded.

The plugin under test refuses to answer instead of recording what it was given.
E12.4 already asserts the deadline value reaching the plugin; what was missing
was the failure the bound exists to prevent, and a plugin that waits on
`ctx.Done()` makes an unbounded verb fail as a call that never came back.

## What surprised me

**A hand-written verb list is the thing under test, not the test harness.** The
first draft reused the shape E12.4 already had — a map of verbs written out by
hand — and it would have passed forever with a new unbounded verb sitting beside
it. The map is unavoidable, because a verb's arguments cannot be invented by
reflection, but it stops being a liability once something else insists it is
complete. Reflection is not driving the calls here; it is auditing the list.

**Exempting a method needs a reason, not an omission.** `Capabilities` and the
three accessors take no context and cannot reach a remote, so they need no
bound. Listing them as exempt is weak — the list would also silently absorb a
new context-less method that does real I/O. Deriving the exempt set from "takes
no context" and then freezing *that* set means a new method has to prove it
sends nothing before it is out of scope.

**The failure mode of an unbounded call is a suite that hangs.** The natural
test is to call the verb and assert the error, and a verb with no bound then
blocks until `go test` kills the binary ten minutes later with a stack dump.
Giving each call a limit of its own turns that into one named subtest failing in
a second, which is the difference between a check that reports and a check that
merely notices.

## What I chose not to build

A lint rule. The ticket says no linter does this, and it is right for the reason
the ticket implies: the property is "this call reached the plugin with a
deadline", which is a fact about a value at runtime and not about the syntax of
a call site. A test that exercises the real route can see it; a linter reading
`b.fsys.Chmod(ctx, path, mode)` cannot tell a bounded `ctx` from an unbounded
one.

Coverage of anything outside the vfs port. It is the only outbound surface in
the repo today. The admin server is inbound and config is local. When a second
one arrives — a model gateway, a broker — it needs its own closure test, because
this one is closed over the verb sets it names.

## What I still do not understand

Whether the closure holds once the wrapper chain grows. `Registry.Build` now
composes retry outside the bound, so the route this test drives is already two
wrappers deep and the breaker will make it three. Each will want its own "no
verb goes around me", and each will reflect over the same four interfaces to ask
it. Three tests with the same reflection preamble is either the right amount of
repetition or a sign that what wants asserting is one claim about the chain
rather than one per wrapper.

What a bound means with retry above it. This test turns retry off so that one
verb costs one bound, which keeps the claim exact but is not what a caller
holds: in production a deaf mount costs `Attempts` bounds plus jitter, and
nothing states a ceiling on that total. Whether the total wants its own bound —
a budget the attempts share rather than one each — is the open half of the
question E12.4 left, and it is a decision about `Build`'s composition order
rather than about either wrapper.
